## 协作规则

1. 区分仓库现状、用户已确认需求、设计建议与待确认事项。
2. 每轮讨论后同步更新相关文档；未确认的建议不自动进入开发范围。
3. 用需求编号关联设计与开发任务，避免实现偏离需求。
4. 外部平台能力需要验证；不把猜测的接口、配额规则或登录方式写成事实。
5. 当前仅进行需求与文档工作，不以文档草稿作为业务开发授权。

## 当前进度

- 已了解：现有工程的技术栈、启动界面及本地 IPC 骨架。
- 已确认：统一查看 Codex 订阅、百炼 Token Plan 个人版与 Coding Plan 中国站，减少分别进入软件或 CLI 查询的操作；其他套餐版本及站点不自动承诺兼容。
- 已确认：首发 macOS，菜单栏快速查看 + 独立管理窗口；后续支持 Windows。
- 已确认：需要查看剩余额度或比例、各额度周期、重置时间或倒计时、最近更新时间与查询状态；支持多个账户。
- 已确认：应用独立管理多账户，可选主动导入已有授权，CLI 不作为正式版的强制依赖；具体方式按平台验证。
- 已确认：默认 5 分钟可调自动刷新、单账户与全部手动刷新、缓存优先与失败反馈；关闭窗口常驻、明确退出，自启可选默认关闭。
- 已确认：低额度与授权失效提醒；重置或恢复提醒可选默认关闭；历史统计不进入首版。
- 已确认：菜单栏快速查看，管理窗口分总览、账户、设置；账户管理提供添加、命名、重新授权与移除。
- 已确认：低额度阈值默认剩余 20% 且可调整；低额度及授权失效提醒默认开启，系统通知需获用户允许；重置提醒默认关闭。
- 已确认：首版开源并提供 macOS 安装包，不仅供本机自用。
- 已补充：规范化数据模型、前后端 IPC 与事件边界、适配器职责、JSON + Keychain 存储建议、刷新提醒方案及测试矩阵。
- 已拆分：13 项候选开发任务和 3 项按具体套餐执行的接入验证任务，包含依赖与退出条件。
- 已确认：macOS 首版同时支持 Apple Silicon 与 Intel，签名公证先参考 devup。
- 已核实：devup 当前工作流按架构构建、默认 ad-hoc 签名且未启用公证，正式签名公证只是预留路径；详见发布参考文档。
- 已确认：Apple Silicon、Intel 分别提供 DMG，ad-hoc 签名暂不公证并说明安装限制，正式签名公证后续升级。
- 正在进行：三个套餐的接入资料核实，最低系统版本、发布渠道及双架构验证条件待进一步确定。
- 已实现：Codex 订阅垂直链路（Rust `refresh_codex_usage` + 前端额度卡，假 app-server 端到端测试通过），真实数据核对待用户本人运行。
- 尚未完成：百炼两类套餐接入、多账户与调度、菜单栏常驻、发布及工期估算。
