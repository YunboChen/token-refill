## 2. 背景与目标

### 2.1 仓库现状

- 当前为 Tauri 2、Rust、React、TypeScript 与 Vite 桌面工程骨架。
- 已有基础窗口、系统浅深色、减少动态效果支持及本地连接检测。
- 已实现 Codex 订阅本机只读查询、Rust 统一状态层、缓存优先、后台自动刷新与失败保留上次成功数据。
- 已实现 Codex 多账户：每个独立账户使用隔离的 `CODEX_HOME`，通过官方 `account/login/start` 浏览器授权；支持添加、改名、重新授权与移除，不复制本机默认登录凭证。
- 低额度、授权失效与重置提醒已接入系统通知（低额度按重置周期去重，授权失效按状态跃迁去重，重置提醒仅在查询确认新周期时发送，均跨重启保持）；开机自启已接入系统登录项，失败会如实反馈且不改本地状态。
- 已实现 Windows 兼容层（CLI 查找、授权链接、数据目录与标题栏按平台适配），Windows 本机构建与单元测试通过；安装包与界面运行验收待补。
- 已实现版本检查与应用内更新：设置页读取 GitHub Releases 最新正式版本并与当前版本比较；安装版可在用户确认后下载（minisign 校验）并重启安装，免安装 Windows exe 仍跳转下载页；应用启动时静默检查，运行期间定期复查；不静默下载或安装。
- 百炼 Token Plan 个人版与 Coding Plan 中国站已通过控制台浏览器授权接入：应用在本机回环地址接收控制台令牌并存入私有目录，分别查询两类订阅额度；不依赖 `bl` CLI，也不读取其配置。
- OpenCode Go 与 Command Code 使用用户填写的 API Key，验证成功后才保存到 `api-profiles/<accountId>/credentials.json`；Antigravity 通过本机 `agy -p /usage --output-format json` 读取官方打印结果，不读取其钥匙串、令牌文件或浏览器会话。
- 菜单栏常驻已实现：左键打开快速查看面板，右键菜单提供打开主窗口、查看额度与退出；关闭管理窗口只隐藏，应用继续后台刷新；macOS 同时隐藏 Dock 图标与 Cmd+Tab 条目，打开主窗口时恢复。
- 系统级凭证安全存储尚未实现（当前授权材料位于应用数据目录的私有文件）。
- macOS 打包最低版本配置为 12.0，不代表已验证兼容。

### 2.2 已确认的产品目标

用户持有多个 AI 套餐，需要分别进入对应软件或 CLI 查询，操作繁琐。Token Refill 提供统一查看入口，减少跨工具切换。

- 首批目标为 Codex 订阅、阿里云百炼 Token Plan 个人版、阿里云百炼 Coding Plan 中国站。用户已确认实际使用的百炼版本，按该范围优先设计与验收，不自动承诺其他版本或站点兼容。
- 首发 macOS，后续支持 Windows。
- 菜单栏快速查看与独立管理窗口并存。
- 首先满足用户自身多套餐、多账户场景，首版同时面向其他用户开源并提供 macOS 安装包；不是仅供本机使用。

三类套餐均属于首批目标。开发可以先打通一类，但不以中间里程碑替代完整首版交付。

### 2.3 当前工作范围

协助完成需求设计，同步维护软件设计与开发计划。已实现 Codex 本机查询、独立账户官方授权、百炼两类套餐查询、统一状态层与基础刷新调度；应用不读取或复制本机默认登录凭证。

## 3. 核心使用场景

1. 用户添加多个账户及其套餐；接入流程按平台能力验证后细化。
2. 日常通过菜单栏快速查看各账户的额度、周期、重置信息与数据状态。
3. 需要详细信息或管理时打开独立管理窗口。
4. 应用按设置自动刷新，也允许刷新单个账户或全部账户。
5. 关闭管理窗口后应用继续常驻；明确退出应用后停止刷新。
6. 低额度或授权失效时可收到提醒；额度重置或恢复提醒可选，默认关闭。

页面组织已确认：菜单栏快速查看，管理窗口包含总览、账户、中转站账户管理、设置；总览内再分「订阅账户额度」与「中转站账户额度」两个标签页，中转站额度展示与账户管理分离。账户操作包含添加、命名、重新授权与移除；低额度和授权失效提醒默认开启，系统通知仍需用户允许。具体视觉布局、账户移除范围、权限与异常流程待细化。

### 4.1 已确认的展示要求

以下四类信息都需要：

1. 剩余额度或剩余比例。
2. 各额度周期，以平台实际提供为准，不预设一定存在某种短周期、周或月额度。
3. 重置时间或距离恢复的倒计时。
4. 最近更新时间与查询状态。

若平台无法提供必需信息，应记录能力缺口并与用户确认处理方式，不伪造、静默删除或用猜测补齐。

补充设计建议：显示可区分的账户与套餐名称，保留原始计量单位，不合并不同单位或周期的额度为一个总数；具体表达方式待确认。

### 4.2 已确认的刷新与数据反馈规则

- 默认每 5 分钟自动刷新，允许用户调整；实际请求服从平台限流和失败退避要求，不承诺所有数据始终只有 5 分钟延迟。
- 支持手动刷新单个账户或全部账户。
- 打开菜单栏先显示已有数据和更新时间；数据过期时异步刷新，不等待全部网络请求完成才展示。
- 中转站额度不参与后台定时轮询：进入「中转站账户额度」或「中转站账户管理」页时先展示上次快照，再把超过刷新间隔的账户自动刷新一次；未打开页面不发起请求。
- 查询失败保留上次成功的数据，标明失败或过期，不把查询失败转换为零额度。
- 首次查询未成功时不显示虚构的历史额度。
- 关闭管理窗口后继续后台刷新；退出应用后不再刷新。

### 4.3 已确认的提醒范围

- 低额度提醒：默认剩余 20% 时提醒，阈值可调整，同一额度周期避免重复提醒；仅在能可靠获得或计算剩余比例时应用百分比阈值。
- 授权失效提醒：需要用户重新授权时提醒，避免长期无提示地使用旧数据。
- 低额度和授权失效提醒默认开启，但系统通知仍需用户允许，设置开启不等于系统权限已授予。
- 额度重置或恢复提醒：首版提供可选开关，默认关闭。
- 触发边界已实现；系统通知权限在应用启动时申请，拒绝后由设置页提示，权限被拒绝不影响额度查询。

### 4.4 Codex Plus 的展示参考

用户提供的当前用量截图确认其套餐为 Plus，界面以“剩余用量”为标题，展示 5 小时与 1 周两类窗口、剩余百分比以及各行右侧时间或日期。这是用户当前界面的参考，不等于协议字段或所有订阅的固定规则。

- 当前 Codex 验证账户以 Plus 为具体对象，其他档位的适用性另行验证，不从该截图自动承诺。
- 百分比须明确已用或剩余，不能颠倒；没有绝对数量时允许只显示剩余比例，不推算 token 数。
- 右侧时间或日期的精确定义、时区及完整时间戳须以可靠来源验证；不从截图补全年份、时区或下一周期时间。
- 不将截图上的周期固定应用于所有 Codex 账户，实际窗口以查询结果为准。
- 开源文档只记录脱离用户身份的展示约束，不存原图、账户名称、真实额度或截图来源路径。

## 7. 接入原则与剩余决策

### 7.1 已确认的接入原则

- 应用独立管理多个账户及查询。
- 对平台允许且技术上安全的来源，提供用户主动触发的已有授权导入。
- 正式版不将安装并登录 CLI 作为统一强制条件。
- 不通过修改外部工具的默认账户或登录配置实现多账户查询，不默认扫描或读取本机凭证。

各平台具体方式须验证，尤其检查授权续期是否影响源工具。独立接入不可行时，展示后备方案的限制，再由用户决定是否调整范围。产品方向确认不构成本机凭证读取操作授权。

当前已实现的 Codex 本机账户与独立授权账户都通过本机 Codex CLI 的 app-server 读取。桌面端自带的 CLI 已纳入查找链，只装桌面端的用户不再需要另行安装 CLI；但本机仍须存在官方客户端（独立 CLI 或桌面端）并完成登录。启动时若本机不存在任何 Codex 客户端，则不显示本机账户，也不发起查询；安装后在下次启动恢复显示。完全去 CLI 依赖的独立授权方案待后续验证，不因本次实现视为已完成。
