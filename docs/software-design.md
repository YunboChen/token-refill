## 1. 设计边界

已确认设计输入：统一查看 Codex 订阅、百炼 Token Plan 与 Coding Plan；支持多个账户；展示额度或比例、各额度周期、重置时间或倒计时、最近更新时间及查询状态；首发 macOS、后续 Windows；菜单栏快速查看与独立管理窗口并存。其余方案仍为建议，不提前固化平台接口、登录流程、数据库或依赖选型。

目标是统一查询入口与展示体验，不假设三类套餐具有相同的计量单位、额度窗口或鉴权方式。

## 2. 现有系统

| 层次 | 现状 | 位置 |
| --- | --- | --- |
| 前端界面 | 总览（订阅账户额度 / 中转站账户额度）、账户、中转站账户管理、设置四页；读取统一状态并订阅变更事件 | `src/panels/` |
| 前端状态入口 | `get_app_state`、`refresh_usage`、`update_preferences`、`set_overview_order`、`set_relay_order`、账户授权/改名/移除命令、中转站查询/编辑/刷新/移除/访问令牌/标题命令与 `app-state-changed`、`account-login-changed` 事件；中转站账户由 `RelayProvider` 在总览与管理页之间共享 | `src/lib/desktop.ts`、`src/lib/store.tsx`、`src/lib/relay.tsx` |
| 本地后端 | Rust 状态存储、后台刷新调度、Codex/百炼/OpenCode Go/Command Code/Antigravity 适配器、中转网关密钥额度适配器、中转站凭证存储与本地配置扫描 | `src-tauri/src/state.rs`、`src-tauri/src/codex.rs`、`src-tauri/src/bailian.rs`、`src-tauri/src/opencode.rs`、`src-tauri/src/commandcode.rs`、`src-tauri/src/antigravity.rs`、`src-tauri/src/quota/`、`src-tauri/src/relay.rs`、`src-tauri/src/discovery.rs` |
| 桌面配置 | 窗口、构建、安全策略及打包配置 | `src-tauri/tauri.conf.json` |
| 权限声明 | 窗口权限与事件监听权限 | `src-tauri/capabilities/` |

现有调用链为：前端启动 → 订阅 `app-state-changed` → `get_app_state` 取缓存快照 → Rust 调度器按间隔或手动请求查询 Codex app-server → 状态落盘并广播。

账户分两类：本机账户沿用现有登录态；独立账户在应用数据目录的 `codex-profiles/<accountId>/` 下拥有独立 `CODEX_HOME`。启动加载状态时按本机是否存在 Codex 客户端（独立 CLI 或桌面端内置 CLI）校正本机账户：客户端不存在则移除占位账户，存在但状态里缺少时补回。未安装 Codex 的用户因此不会看到必然失败的账户，调度器也不会反复查询；卸载后重新安装会在下次启动恢复。客户端存在但未登录时仍保留账户并展示授权错误，便于用户完成登录。每次查询会在同一 app-server 会话中先读取 `account/read` 获取脱敏邮箱与套餐档位，再读取额度；即使额度请求失败（如网络异常），只要身份读取成功，账户页仍能显示当前登录账号，身份读取本身失败则保留原值，不误清空。添加或重新授权时，Rust 启动该目录下的 app-server，调用官方 `account/login/start` 取得浏览器授权 URL，等待 `account/login/completed` 后读取身份与额度。登录令牌由 Codex CLI 写入隔离目录，应用不解析、不复制、不向前端返回；`account-login-changed` 仅携带流程标识、账户标识、状态和脱敏错误。

百炼账户属于独立授权账户：Rust 在 `127.0.0.1` 随机端口启动一次性回调服务，打开官方控制台登录页；浏览器把控制台 `access_token` 回传到该地址，`state` 校验通过后才写入 `bailian-profiles/<accountId>/credentials.json`（Unix 目录 0700、文件 0600）。一个百炼账户下有两个产品：Token Plan 与 Coding Plan。每次刷新顺序请求两类额度接口，任一失败只影响对应产品并保留其上次成功快照；两者都判定会话失效时才把账户标为需要重新授权。令牌不进入 `PersistedState`、IPC 返回值、事件或日志；移除账户会删除该目录。

OpenCode Go 与 Command Code 属于 API Key 账户：添加时先用一次真实查询验证密钥，成功后写入 `api-profiles/<accountId>/credentials.json`（同样 0700/0600），失败不会留下账户或凭证。OpenCode Go 读取官方 `GET https://opencode.ai/zen/go/v1/usage` 的 5 小时 / 每周 / 订阅月百分比；Command Code 读取 CLI 同款 `/alpha/billing/credits`、`/alpha/usage/summary` 与 `/alpha/billing/subscriptions`，月度上限由“已用 + 剩余”推导，辅助接口失败时保留滚动窗口并记录能力缺口。密钥只在 Rust 侧使用，不进入 `PersistedState`、事件或错误消息。

启动后 Rust 会在后台探测本机已有登录态：OpenCode 调用官方 `opencode auth export`，存在活动 API Key 时自动创建“本机 OpenCode”账户，并在每次刷新时重新读取 CLI 凭据；Antigravity 先确认 `agy` 可执行，再实际读取一次 `/usage`，成功才创建“本机 Antigravity”账户。未探测到时不创建账户，保持“添加账户”的手动流程。探测只使用官方 CLI 命令，不直接解析 SQLite、钥匙串或浏览器 Cookie。

Antigravity 是本机账户：应用只调用 `agy -p /usage --output-format json` 读取官方打印结果，不读取 CLI 的钥匙串、令牌文件或浏览器会话。查询前校验 `agy --version` ≥ 1.1.11，并设置 `AGY_CLI_DISABLE_AUTO_UPDATE=true`；查询带超时并能主动结束未登录时等待交互的进程。返回按模型分组展示每周 / 5 小时剩余比例与重置时间。

网络代理由设置页统一配置（跟随系统 / 不走代理 / 指定代理），状态层在启动与偏好变更后写入全局代理配置。ureq 请求按目标 URL 选择代理并跳过回环地址与 `NO_PROXY`；跟随系统时 `ALL_PROXY` 可能是 `socks5://`，ureq 已开启 `socks-proxy` 特性以支持该形式（未开启时对手动配置的 SOCKS 代理会直接 panic）。子进程（`agy`、Codex app-server）在构造 `Command` 时写入或移除代理环境变量，并把 CLI 自身目录与 nvm / fnm / Volta / Bun / pnpm、Homebrew 等常见安装目录补到 `PATH` 前面：从 Finder 启动的 GUI 进程只有系统目录，npm 安装的 CLI 是 `#!/usr/bin/env node` 脚本，解释器找不到时会以退出码 127 结束。补齐只作用于子进程，不改动应用进程的环境。跟随系统时按目标协议先使用进程已有的 `HTTP(S)_PROXY`，两者都缺失时才回落到 `ALL_PROXY`（与 curl 一致，避免 `ALL_PROXY` 指向未启用的 SOCKS 端口时盖过可用的 HTTP 代理），之后才读取 Windows Internet Settings 或 macOS `scutil --proxy`；PAC/自动配置脚本不解析。指定代理只接受不含凭据的 HTTP/HTTPS URL。

### 3.1 macOS 首发与后续 Windows

系统相关能力（凭证存储、菜单栏或托盘、窗口定位、通知）与额度业务保持分离；macOS 首发只实现本期实际需要的能力，不预先搭建跨平台抽象层。

Windows 兼容层已落地，变化集中在四处，业务状态模型不变：

- Codex CLI 查找按平台区分候选名（`codex` 与 `codex.exe` / `.cmd` / `.bat` / `.com`）、可执行判定与常见安装目录，覆盖 npm、pnpm、Volta、Bun、Scoop、nvm-windows、fnm 及官方安装包。Codex 桌面端（ChatGPT.app / Codex 桌面应用）自带的 CLI 排在查找链最后：macOS 探测 `Contents/Resources/codex-cli/bin`，Windows 探测安装目录的 `resources\codex-cli\bin` 与 Microsoft Store 的 `WindowsApps\OpenAI.Codex_*`；桌面端与独立 CLI 共用登录态，只装桌面端也能查询本机额度，但仍通过官方 `app-server --stdio` 读取，不解析桌面端内部状态文件。
- 授权链接在 Windows 上交给 `ShellExecuteW`，避免 `cmd /C start` 把 URL 查询串里的 `&` 当作命令分隔符。
- 数据继续写入 `app_data_dir()`（Windows 为 `%APPDATA%\<identifier>`；测试版为 `...\dev.tokenrefill.desktop.test`）；Unix 权限位保持不变，Windows 依赖该目录的按用户 ACL。
- 窗口在 macOS 保持 Overlay 原生标题栏；Windows 在 Rust `setup()` 中关闭系统装饰，由前端 `TitleBar` 自绘标题栏。前端读取 `get_app_info().platform` 切换两套布局，首帧用 UA 兜底。主窗口以 `visible: false` 创建，Windows 在前端首帧后由 `main-ui-ready` 事件触发显示（5 秒兜底），macOS 在 `setup()` 中直接显示。应用名、版本与 `channel` 同样来自 `get_app_info()`。

分发渠道：正式版与测试版共用代码，测试版通过 `src-tauri/tauri.test.conf.json` 覆盖 `productName` 与 `identifier`，数据目录、单实例锁、通知权限与开机自启随之隔离；渠道由 Rust `channel.rs` 按 identifier 的 `.test` 后缀判定，不引入第二套构建期开关。测试版版本号由 CI 注入为 `<基础版本>-test.g<短提交>`，不写回源文件；测试渠道不发起 GitHub 版本检查，下载与安装命令直接拒绝应用内更新。

Windows 安装包与界面运行验收尚未完成，最低 Windows 版本待确定。macOS 仍须分架构构建并分别运行验收，不把交叉编译通过等同于 Intel 运行已验证。详见 [Windows 兼容设计](./windows-support.md)。

### 3.2 菜单栏与快速查看面板（已实现）

- Rust `tray` 模块用 Tauri 的 `tray-icon` 能力创建菜单栏图标：macOS 使用随包附带的单色模板图标并按系统外观自动反色（测试版使用右下角带圆点的变体，正式版与测试版可同时常驻）；Windows 使用应用图标。右键菜单提供「打开主窗口」「查看额度」「退出 <应用名>」，应用名取合并后的 `productName`。
- 快速查看面板是在 `tauri.conf.json` 中声明为 `create: false` 的窗口 `tray-panel`：380×560、无边框、透明背景、置顶、跳过任务栏，加载同一前端产物的 `index.html?view=tray`。第一次点开时才按配置创建，隐藏 60 秒后销毁 WebView；重建时窗口保持隐藏，等页面加载完成（或 1.5 秒兜底）后再定位显示，避免透明窗口闪空白。前端按 URL 参数渲染 `TrayPanel`，与主窗口共用 `AppStateProvider` 与 `RelayProvider`。
- 左键点击图标切换面板；macOS 用 `NSScreen` / `NSEvent` 的原生坐标把面板放在鼠标所在屏幕的菜单栏下方并水平对齐图标，避免 Retina 与普通屏混排时 Tauri 物理坐标不一致；其他平台按托盘矩形与目标显示器可用区域计算。
- macOS 快速面板通过仅限 macOS 的固定版本依赖 `tauri-nspanel 2.1.1` 转换为非激活 `NSPanel`：保留 Tauri 的 delegate、WebView 与窗口所有权，设置 `NonactivatingPanel` 与 `CanJoinAllSpaces | FullScreenAuxiliary`，清除互斥空间属性、保留无关属性。显示使用 `orderFrontRegardless` 与 `makeKeyWindow`，不调用会激活整个应用的 Tauri `set_focus()`，避免从全屏空间切回主窗口所在桌面。仅给普通 `NSWindow` 设置置顶或全屏辅助属性并不足以保证覆盖其他应用的全屏窗口。此路径只作用于快速面板，不修改 `LSUIElement` 或主窗口的激活策略，也不增加前端 IPC 权限；依赖启用 Tauri 的 `macos-private-api`，并包含 AppKit 私有 API 兼容路径，不作为 App Store 发行方案。
- 面板空闲销毁前先从插件注册表移除强引用、恢复原始窗口类，再由 Tauri 销毁窗口与 WebView；首次创建与销毁后重建均重新转换为 `NSPanel`。自动化测试覆盖原生面板类型、空间属性组合、互斥位清理、无关位保留与重复设置。2026-10-29 用户按 macOS 实机清单验证并反馈全部正常：主窗口显示 / 关闭时的全屏覆盖、面板内交互、失焦 / Esc / 图标收起与重开、隐藏超过 60 秒后的重建及多屏场景。`pnpm build`、完整 Rust 测试（192 项单元测试 + 12 项集成测试）、`cargo fmt --check` 与 `cargo clippy --locked --all-targets -- -D warnings` 均通过；该结果不代表 Windows 或其他 macOS 版本已完成验收。
- 面板失焦自动收起，但只有“确实获得过焦点且距上次显示已超过 400 ms”才收起：托盘点击唤出的窗口在 Windows 上可能因前台锁停在未激活状态，此时收到的失焦是杂散事件，收起会让左键看起来毫无反应。非 macOS 在显示后没拿到激活态会补一次聚焦（仍失败也不隐藏，置顶窗口至少可见、可再点托盘收起）；macOS 的非激活 `NSPanel` 由 `makeKeyWindow` 取得 key 焦点，因此既不读 `is_focused` 也不补焦——补焦会激活应用并切回主桌面空间。另外记录失焦时间避免“点击图标关闭”时又立刻重开；按 Esc 收起。
- 创建与显示请求一律经后台线程转投主线程，不在托盘回调里就地创建：托盘回调本身在主线程，`run_on_main_thread` 会内联执行，而创建窗口要等 WebView2 初始化（零 WebView 冷启动更慢，内部还会自行泵消息），就地执行会卡住托盘菜单，重入的点击还会重复创建窗口、作废正在加载那一代的显示回调。加载标志改成在创建入口处判断，创建期间的再次左键点击视为取消。
- 窗口与托盘的生命周期事件写 `logs/window.log`（同时输出 stderr）：发布包在 Windows 上是 GUI 子系统，没有控制台，`eprintln!` 会被丢弃，没有文件日志就无法判断“点击是否到达事件循环”。
- 关闭主窗口只隐藏，隐藏满 60 秒后销毁 WebView（有登录流程或更新下载在进行时跳过），再次打开时按配置重建并等待页面加载；应用继续在菜单栏驻留并刷新。销毁最后一个窗口会让 Tauri 请求退出，`RunEvent::ExitRequested` 在“没有窗口且非程序化退出”时调用 `prevent_exit`，避免空闲销毁把常驻应用结束掉。只有菜单或面板中的退出入口会结束进程并停止调度。macOS 关闭主窗口时把激活策略切到 `Accessory`，Dock 图标、Cmd+Tab 与应用菜单栏一并消失；显示主窗口前先切回 `Regular` 再显示并聚焦，否则窗口拿不到 key 焦点，也没有应用菜单栏。
- 面板打开时先展示现有额度与更新时间，再按刷新间隔补查中转站账户；订阅账户继续由 Rust 调度器后台刷新。版本检查只由主窗口发起，面板不重复请求 GitHub。

## 4. 平台接入验证

每个平台在进入详细设计前，需要记录：

1. 具体产品与套餐，区分订阅额度、API 余额及其他计量方式。
2. 可用的数据来源、调用许可与鉴权要求。
3. 是否能获取额度上限、剩余额度、多个额度窗口及重置时间。
4. 响应字段与单位的真实含义，哪些值只能估算或根本不提供。
5. 凭证有效期、续期方式、限流和典型错误。
6. 所需权限及对用户日常工具、浏览器或配置文件的影响。

Codex 与百炼两类套餐均已完成真实读取验证，百炼的协议与字段记录见 [平台接入可行性记录](./platform-integration-validation.md) 第 7 节。若后续平台变更导致无法满足可靠性或权限要求，应回到需求阶段调整范围，而不是用猜测数据补齐。

### 4.1 首批验证对象

| Codex 订阅，当前测试 Plus | 用户截图确认 Plus，当前界面按剩余百分比展示 5 小时及 1 周窗口；无身份化展示约束见需求文档 | 允许的查询来源、鉴权及续期、百分比口径、实际窗口与时间语义；截图不作为已验证协议 |
| 百炼 Token Plan 个人版 | 已核实：控制台网关 API 返回订阅月已用比例（0..1）与重置时间；控制台浏览器登录可拿到所需令牌 | 第二个账号的隔离、令牌有效期与续期、限流；不返回绝对 Credits 余额 |
| 百炼 Coding Plan 中国站 | 已核实：控制台网关 API 返回有效订阅的调用次数与 5 小时、周、订阅月三个窗口，以及套餐档位 | 第二个账号的隔离、令牌有效期与续期、限流；不提供 token 消耗或单模型用量 |

百炼接入不依赖 `bl` CLI，而是直接使用控制台登录回调和网关协议；已在用户本机环境完成真实读取。运行模型推理所用的 API Key 与查询套餐用量所需的控制台授权不能等同，应用会明确区分。

### 4.2 已确认的接入原则，具体实现待能力验证

用户已确认“应用独立管理多账户 + 可选主动导入”，不将 CLI 作为正式版统一的强制运行依赖。下述规则限定后续设计与验证，不代表已具备各平台接入能力，也不构成读取本机凭证的操作授权。

- 应用负责保存各账户记录、协调查询、展示结果及反馈授权状态。
- 平台提供适用且允许的授权方式时，优先采用；不能假设存在可供第三方应用使用的登录流程或订阅用量 API。
- 用户主动选择导入来源并同意范围后，才读取必要授权；不默认扫描本机、浏览器或现有工具。
- 若导入安全性无法成立，尤其是刷新令牌轮换会影响源工具时，不把复制凭证作为接入方案；改为单独授权或回到需求讨论替代路径。
- CLI 可用于接入能力验证，或在确有必要且用户接受时作为受控后备适配。需要明确其安装、版本、账户选择、超时及凭证边界，不通过修改默认登录态轮流查询多个账户。
- 应用内独立管理账户并不等于已经具备独立授权能力；三类套餐必须分别验证后才能定案。

该方向有利于多账户隔离、后台查询和后续 Windows 支持。代价是需要承担各平台授权、接口兼容与维护工作，不能仅为去掉 CLI 而依赖不稳定或不允许的数据来源。

### 4.3 接入资料初查

已形成 [平台接入可行性记录](./platform-integration-validation.md)。该记录区分文档线索、真实读取验证与仍未覆盖的场景；百炼两类套餐已在用户本机环境完成真实查询。

验证对设计的关键约束：Token Plan 个人版只提供订阅月已用比例与重置时间；Coding Plan 按调用次数计量，包含 5 小时、周与订阅月窗口。两者不能合并为 token 总数。Codex 使用本地 app-server 协议，不作为公开 HTTP API 承诺。具体见记录中的来源与限制。

不能使用“所有套餐都是 token 余额”“一个推理 Key 即可查询全部用量”或“所有平台只有一种周期”的固定假设。

### 4.4 中转网关密钥额度适配器

Rust 侧实现两类中转平台适配器，代码在 `src-tauri/src/quota/`（`newapi.rs`、`sub2api.rs`），并在“中转站账户管理”页提供自动识别与手动输入两种入口，额度在总览的「中转站账户额度」标签页展示。识别时依次请求 New API 与 Sub2API 的额度接口，成功即确定平台类型；都失败时只返回来源与原因，不回显密钥或响应正文。

- **New API（密钥口径）**：`GET /api/usage/token/`（Bearer）返回 `total_granted` / `total_used` / `total_available` / `unlimited_quota` / `expires_at`；额度单位为平台内部 quota，用公开接口 `GET /api/status` 的 `data.quota_per_unit` 换算，取不到时按上游默认 `500000` 兜底。密钥开启 `allow_user_quota_query`（面板文案「允许查询用户额度」，New API ≥ v1.0.0-rc.45）时，响应还会带上 `user_quota.total_available` / `total_used`。部分站点（例如部分二开站点）会直接返回 `quota_scope: "account"`，此时 `total_*` 是账户口径；若同时带 `display`（已按币种换算的 `remaining` / `used` / `total` / `unit`），优先使用 `display`。这种响应即使 `unlimited_quota=true` 也视为拿到了账户余额，不再按“无限额密钥”丢弃。币种从 `display.unit` 或 `/api/status.quota_display_type` 读取，界面按 USD / CNY 显示对应符号。两者都没有时只显示密钥额度，并给出对应的版本提示。
- **New API（访问令牌口径）**：用户可选填访问令牌。新版为 scoped PAT（New API ≥ v1.0.0-rc.41，令牌以 `nap_` 开头）；旧版/部分站点仍使用个人设置里的单个系统访问令牌。旧版单令牌必须同时填写用户 ID，应用按 `New-Api-User: <用户 ID>` 发送；新版会忽略该头。`GET /api/user/self` 读取 `quota`（钱包剩余）与 `used_quota`（累计已用），需要 `profile:read`；`GET /api/subscription/self` 读取生效中的订阅，需要 `wallet:read`，接口不存在或失败时只返回空订阅窗口，不影响账户余额。密钥已经返回账户额度时不再请求访问令牌；否则优先使用令牌，失败时把原因记录在 `accountError`。
- **Sub2API（仅密钥）**：`GET /v1/usage`（Bearer）按 `mode` 返回三种口径。`quota_limited`（密钥设了总额度或任一 5h/1d/7d 限速）只返回密钥总额度与限速窗口；`unrestricted` + 订阅分组返回账户订阅的日/周/月用量与上限（`remaining = -1` 表示无周期上限，日/月重置边界平台不提供，不推算）；`unrestricted` + 普通分组返回账户钱包余额（`balance`）。因此 Sub2API 只有在密钥无总额度、无限速且属于普通分组时才通过密钥拿到账户余额，其余情况展示对应额度，不引入账号密码登录。

凭证与存储：

- 手动填写的服务地址、API Key、New API 访问令牌与用户 ID 保存在 `relay-profiles/<relayId>/credentials.json`（Unix 目录 0700、文件 0600，Windows 沿用 `%APPDATA%` 的按用户 ACL），先写临时文件再原子替换。凭证只在 Rust 侧读取，不进入前端状态、事件、日志或错误消息。用户设置的账户标题（最多 40 个字符，非凭证）与凭证同文件保存；扫描导入的条目保存在 `source.json` 的来源引用里，重启后优先使用已保存的标题。编辑手动账户的服务地址或 API Key 会立即重新识别并刷新额度；来源引用账户的地址与密钥始终从源配置读取，界面只允许修改标题，避免应用内的值覆盖真实来源。
- 从 cc-switch、Claude Code / Codex 配置扫描到的密钥不复制到应用目录。用户勾选导入后，`relay-profiles/<relayId>/source.json` 只保存来源引用（来源、app_type、provider id、导入时的地址、provider 类型与用户主动填写的访问令牌），同一目录的 `snapshot.json` 保存脱敏额度快照；启动与每次刷新前按引用重新读取源配置取出密钥；启动时取不到就跳过该账户，刷新时记录错误并保留上次快照。界面用「凭证已保存 / 来源已保存 / 凭证仅本次运行」区分手动凭证、来源引用与仅内存条目。
- 扫描是管理页上的手动入口：点击「扫描本地配置」后只列出候选（来源、provider 名称、地址、是否已在列表中），不发起网络请求、不自动登记；用户勾选并确认导入后，Rust 才对选中的候选识别上游并查询额度。扫描候选的密钥保留在 Rust 内存中，前端只拿到不含密钥的视图。
- 打开“中转站账户管理”页，或切到总览的「中转站账户额度」标签页时，只加载已保存条目及上次成功快照；启动时仅在存在 `source.json` 的情况下读取对应源配置（只读、不发网络请求），随后每次刷新（含自动刷新）前也会重新读取来源账户的源配置；没有来源账户时不扫描。随后把距上次成功查询已超过刷新间隔（沿用设置中的分钟数）的账户批量刷新一次；自动刷新失败按同一间隔退避，切换页面不会重复请求。两处共用同一份前端状态，添加、扫描导入、编辑地址与密钥、手动刷新、补充令牌、设置标题或移除后立即同步。主窗口与菜单栏面板各自持有前端副本，真正共享的是 Rust 侧注册表：条目变化后广播 `relay-accounts-changed`（带修订号与完整脱敏视图），另一侧据此更新；窗口重新显示时再读取一次列表与状态快照，兜底隐藏期间可能漏掉的事件。手动刷新失败保留旧快照并记录脱敏错误。移除条目会删除对应的 `relay-profiles/<relayId>/` 目录。
- 访问令牌只对 New API 生效；Sub2API 账户不接受或保存访问令牌。

New API 二开兼容策略（响应字段不是上游协议的一部分，按“可缺省、可别名、未知即忽略”解析）：

- 账户口径按优先级判断：`user_quota` → `quota_scope` 为 `account` / `user` / `shared` → 无限额密钥且存在 `display` 金额时推断为账户口径。`quota_scope` 为 `token` / `key` 时明确按密钥口径处理。
- `display` 兼容 `remaining` / `remain` / `available`、`total` / `granted` / `quota`、`used` / `used_quota` / `consumed`、`unit` / `currency` / `symbol`；数值可以是 JSON 数字或数字字符串。
- `/api/user/self` 的余额读取 `quota` 或 `balance`，拆分余额时用 `paid_balance + bonus_balance`；已用读取 `used_quota` 或 `used`。
- `unlimited_quota` 接受布尔、0/1 和 `"true"` / `"false"`；时间字段接受数字或字符串。
- 币种优先取 `display.unit`，其次 `/api/status.quota_display_type`；`¥` / `￥` / `RMB` 归一为 `CNY`，`US$` 归一为 `USD`，未知币种按原样显示。
- 未知字段一律忽略，不会导致整次查询失败；只有无法识别信封（缺少 `data`）或密钥请求本身失败时才返回错误。若二开站点改用完全不同的字段名或接口，需要提供真实响应样例后再适配，不做猜测。

本地配置读取范围（`src-tauri/src/discovery.rs`）：

- cc-switch：`~/.cc-switch/cc-switch.db`（SQLite）`providers` 表中 `app_type` 为 `claude` / `codex` 的行，只读打开、不加写锁，不修改也不复制数据库。Claude 行取 `settings_config.env.ANTHROPIC_BASE_URL` 与 `ANTHROPIC_AUTH_TOKEN`/`ANTHROPIC_API_KEY`；Codex 行取 `settings_config.auth.OPENAI_API_KEY`，地址取自 `config` TOML 中激活的 `[model_providers.<id>]`（回退顶层 `base_url` / `openai_base_url`）。数据库不存在、结构不匹配或被占用时当作本轮没有候选，不影响页面。
- Claude Code：`$CLAUDE_CONFIG_DIR/settings.json` 或 `~/.claude/settings.json` 中 `env.ANTHROPIC_BASE_URL` 与 `env.ANTHROPIC_AUTH_TOKEN`（回退 `ANTHROPIC_API_KEY`）。
- Codex：`$CODEX_HOME/config.toml` 或 `~/.codex/config.toml` 的 `[model_providers.<id>]`，只取 `base_url` 与 `env_key`/`experimental_bearer_token`；激活的 `model_provider` 排在最前。不读取 `auth.json` 等登录态凭证，也不执行配置中的命令。
- 客户端 Base URL 末尾的 `/v1` 会被去掉后再拼接额度接口，避免 `/v1/v1/usage`。

导入时识别失败会在管理页列出未识别的配置及原因，用户仍可手动填写地址与密钥。两类适配器都只把规范化后的金额、窗口与到期时间交给调用方；手动凭证持久化在应用数据目录，扫描候选与导入后的密钥仅存在于 Rust 内存，均不进入前端状态、日志或错误消息；错误信息不回显响应正文。服务地址仅允许 HTTPS，本机回环地址例外。

## 5. 数据设计待定项

核心展示范围与多账户要求已确认，具体字段和持久化方式待平台验证。需要覆盖的概念包括：

- 账户标识与展示信息；敏感凭证不混入前端展示对象。
- 平台特有的额度窗口、单位和计量口径。
- 数据获取时间、来源及是否过期。
- 平台给出的重置时间与未知状态；不无依据推算。
- 查询失败、鉴权失效、限流和部分成功等状态。

不同单位或周期的额度不直接相加，不假设所有平台都能转换成 token 数。

### 5.1 多账户与套餐关系建议

- 区分平台身份、账户下的套餐与套餐下的额度窗口，不把账户等同于一个套餐。
- 同一百炼账户若持有 Token Plan 与 Coding Plan，关联为同一账户下的两个产品，共享一次控制台授权；任一产品无订阅时保留为独立的数据缺口。
- 每个账户与套餐的数据、更新时间、错误和授权状态都可独立定位，不使用单一全局“当前账户”承载所有查询。
- 账户凭证以隔离的安全引用访问，不进入前端数据对象；刷新去重与缓存也需要带账户及套餐标识。
- 相同账户的重复添加检测、显示名称、排序、移除与重新授权规则待交互讨论，不预设邮箱一定存在或可作为唯一标识。

### 5.2 必需验证场景

- 两个同平台账户同时接入，数据不会串到另一个账户。
- 一个账户授权失效或查询失败时，其他账户仍可查询并展示。
- 一个账户下的多个套餐、一个套餐下的多个周期不互相覆盖。
- 查询失败时不更新最近成功时间，也不把旧快照标成最新。
- 若采用已有授权导入，验证源工具的登录与续期不会因本应用受到破坏。

### 5.3 内部数据模型草案

以下是应用内部的规范化设计，不是任何平台真实响应的声明。所有可选字段需保留未知语义；真实响应到内部模型的映射在接入验证后确定。

| 对象 | 建议核心内容 | 约束 |
| --- | --- | --- |
| Account | 本地随机/生成 `accountId`、平台、显示名、授权来源（本机或独立授权）、可选脱敏身份标识、授权状态 | 不以邮箱作唯一主键；不在前端对象中携带凭证或安全存储引用 |
| Product | 本地 `productId`、所属账户、产品类型、可选套餐档位及远端标识 | 首批类型为 Codex 订阅、Token Plan 个人版、Coding Plan 中国站；远端标识不可靠时不猜测 |
| QuotaWindow | 本地窗口标识、来源窗口标识、可选平台窗口名、计量单位、可选总量/已用/剩余/比例、可选周期及重置时间 | 不强制存在绝对额度；比例必须来源可靠或能在相同口径下推导。百炼 Coding Plan 保留调用次数与三个窗口，Token Plan 只有比例 |
| QuotaSnapshot | 对应产品、额度窗口列表、最近成功获取时间、可选来源更新时间、能力缺口 | 只保留所需快照；来源更新时间未知时不能把本地查询时间冒充平台更新时间 |
| QueryState | 当前是否刷新、最近尝试时间、脱敏错误、可选下次允许重试时间 | 与成功快照分开保存，失败不抹掉上次成功数据 |
| Preferences | 刷新间隔、三类提醒开关、低额度阈值、自启意图 | 初始值采用已确认需求；OS 实际通知和自启状态另行查询，不能只信本地开关 |
| OverviewOrder | 用户拖动后的平台键顺序与账户标识顺序 | 只保存标识与相对顺序，不含账户名、邮箱或凭证；未列出的标识保持默认顺序并排在已列出项之后；重复提交相同顺序不写盘 |
| RelayOrder | 总览「中转站账户额度」中的账户标识顺序 | 只含中转站注册表标识，不含标题、地址、密钥或额度；不影响注册表本身与凭证；未列出的账户保持注册表顺序并排在后面 |
| NotificationReceipt | 账户、产品、窗口、提醒类型、可靠周期标识或经确认的退化标识、已发送状态 | 支持重启去重；周期未知时不能构造虚假的周期身份 |

### 5.4 规范化与一致性规则

- 本地时间戳统一采用带时区的 UTC 表达，前端按系统时区展示；平台返回秒或毫秒必须由适配器明确转换。
- 数值缺失、不支持与真实零值分别表达；无法可靠计算时不生成比例或重置时间。
- Codex Plus 截图参考使用剩余比例。若适配来源提供的是已用比例，须在验证其字段含义与范围后转换，再用于展示和低额度判断，不能直接把已用百分比标成剩余或反向触发提醒。
- 来源仅给比例时不推算绝对 token 余额；截图中仅有时分或月日时不补造时区和完整时间戳。
- Token Plan 个人版的订阅月不按自然月计算。Coding Plan 的多个窗口不与个人版周期混同。Codex 的窗口标签不固定绑定某一种持续时长。
- 同一账户的不同产品、同一产品的不同窗口独立标识；不能按平台名覆盖数据。
- 数据格式或范围异常时产生解析错误或能力缺口，不用静默补零、强行截断等方式伪装成正常额度。
- 来源查询时间与来源实际更新延迟分开考虑。最近成功获取不代表上游计费数据实时结算。
- 补充包和 Harness 的展示范围尚未确认，不提前实现；也不以主套餐剩余为零推断全部服务不可用。

## 6. 安全与隐私设计方向

仓库 README 已提出前端不应持有账户密钥，平台请求和凭证访问优先放在 Rust / 系统层。建议在需求确认时将以下内容明确为可验收约束：

- 敏感凭证留在系统安全存储或经确认的本地安全方案中，不进入普通配置、日志或前端状态。
- 账户接入应由用户主动授权，不默认扫描浏览器、工具配置或其他账户信息。
- 外部查询权限、网络目标与 Tauri 权限按实际功能最小化配置。
- 移除账户时明确凭证、缓存与配置各自的删除范围。
- 遥测、云同步与诊断上报不默认引入；如确有需求，单独讨论数据与授权范围。

首发系统已确定为 macOS，Keychain 仍为后续系统级凭证存储的候选方案。当前 Codex 独立账户由 Codex CLI 在应用数据目录的 `codex-profiles/<accountId>/` 中维护授权文件，目录权限 0700；应用本身不解析或复制令牌。移除账户时删除对应目录，不影响本机默认登录。Windows 使用同一目录结构，授权目录与状态文件继承 `%APPDATA%\dev.tokenrefill.desktop\` 的按用户 ACL，不额外设置 ACL；若 `APPDATA` 被重定向到权限更宽的目录，本应用不做加固。用户已接受主动导入已有授权的产品方向，但每种来源的具体读取范围、系统权限及续期方式仍需明确，实际读取应由用户主动授权。

### 6.1 本地持久化方案建议

- 鉴于首版没有历史统计、云同步或复杂检索，已使用 Rust 管理的带版本 JSON 状态文件保存账户元数据、设置、所需最新快照与查询状态，未引入数据库。当前实现为先写临时文件再原子替换，Unix 下文件权限设为 0600（Windows 沿用 `%APPDATA%` 的按用户 ACL）；损坏或版本不兼容时先备份原文件再回到默认状态。
- 以上数据虽不是凭证，仍包含账户及用量隐私，应位于应用专属数据目录、限制访问、不进入源码目录、共享导出或普通日志。
- 凭证单独放入 macOS Keychain，后端按账户及授权用途隔离访问；普通状态文件只存后端内部引用，前端不可取得密钥或安全引用。
- 使用单写入入口与原子替换，防止两个窗口或刷新任务并发覆盖设置；备份与恢复只处理非凭证文件，格式版本不兼容时不直接覆盖旧数据。
- Keychain 与普通文件不是一个原子事务。添加失败、更新失败或移除失败需要可恢复步骤，不得把写入失败报告为成功，也不能误删其他产品仍使用的凭证。
- 移除账户时先停止后续查询并使旧任务失效，再清理本应用的数据与适当的自有凭证；不清理源工具配置，不默认触发全局注销。
- 不保存完整平台原始响应或长期明细来代替字段设计。测试、错误报告和发布材料必须使用明确的合成数据或脱敏内容。
- 具体 JSON 格式、安全存储库及数据迁移步骤在实现前核实；Windows 通过同一职责边界适配，不把 macOS Keychain API 泄漏到前端。

## 8. 刷新与提醒工程方案

以下为实现建议，不代表接口、库或存储方式已完成选型。

已落地：Rust 侧单一调度入口、按账户去重、后台线程查询、快照与查询状态分离、失败保留成功数据、JSON 原子替换与变更事件。仍待完善：平台限流与退避参数、休眠唤醒/重新联网后的补偿策略、重新授权与移除账户时的在途任务失效。

### 8.1 刷新协调与状态

- 调度器位于 Rust 后端，不随前端窗口关闭而停止；自动刷新、单账户刷新、全部刷新与过期触发均进入同一协调入口。
- 按账户与套餐识别任务，合并同一对象的在途请求，限制并发并错开集中请求；手动操作也不能绕过平台限流。
- 分开保存最近成功快照及时间、最近尝试时间、当前请求状态与错误；失败不覆盖成功快照，不更新成功时间。
- 首次无快照、正常数据、刷新中、数据过期和最近查询失败可以组合表达，不以一个互斥状态掩盖旧数据或错误。
- 网络失败、限流与授权失效分别处理；优先采用平台返回的重试约束，其他情况再按有上限的退避策略处理，参数待验证。
- 真正授权失效时应停止无意义的重复认证请求，提示重新授权；不把普通超时当成需要登录。
- 移除账户或重新授权后，不接受旧在途请求回写已移除账户或新授权的数据；具体取消与版本校验方式在实现前确定。
- 退出应用时停止新任务、处理在途请求并完成必要状态保存，不启动独立后台守护进程。

### 8.2 提醒判断与去重

- 只使用可信的新数据或明确的授权失效结果判断提醒，过期缓存与查询失败不触发低额度提醒。
- 按账户、套餐、额度窗口与提醒类型区分记录；低额度提醒在同一可识别周期内去重，不能只按平台去重。
- 启用重置或恢复提醒时，应依据新查询结果与可识别周期变化确认，不仅因本地倒计时归零就宣称额度恢复。
- 不能可靠识别周期或剩余比例时，记录限制并确定替代规则，不猜测阈值与重置事件。
- 建议将必要去重状态持久化，避免应用重启后重复提醒；不为此引入历史统计或保存完整响应。
- 低额度与失效提醒默认开启，低额度阈值默认剩余 20% 可调；重置或恢复提醒默认关闭。通知设置与系统权限分开表达，不能因开关已开启就宣称系统允许通知。
- 系统通知权限在应用启动时申请一次；拒绝后在设置页提示，不阻断额度查询。macOS 使用 `UNUserNotificationCenter`，前台同样展示横幅；旧 `NSUserNotification` 在前台只写入通知中心。

### 8.3 验证重点

- 两个窗口同时打开和连续点击刷新，不产生同对象重复请求。
- 单账户错误、限流或失效不会串到其他账户；全部刷新可以展示部分成功。
- 关闭管理窗口仍调度，退出后不再产生查询；休眠恢复不积压补发大量错过的任务。
- 网络失败保留快照与成功时间，首次无数据不显示零额度。
- 重复刷新或应用重启不重复通知；重置提醒默认关闭；普通网络故障不触发授权失效通知。
- 自启开关初始关闭，系统拒绝或修改失败时不假装已保存成功。

| get_system_permissions / request_notification_permission | 读取状态或用户明确触发的权限请求 | 区分应用设置与系统许可；不在额度查询失败时反复弹出权限申请 | REQ-006、REQ-010 |
| open_management_window / quit_app | 用户明确操作 | 窗口复用或退出清理，不能把关闭管理窗口等同于退出 | REQ-005、REQ-009 |
| check_for_update（已实现） | 无敏感输入 | 读取 GitHub Releases 最新正式版本的版本号与发布页地址；只比较与展示，不下载、不安装。测试渠道直接返回“无更新”，不发起网络请求 | REQ-012 |
| download_update（已实现） | 无敏感输入，用户点击触发 | 从 `latest.json` 取最新更新包，按应用代理设置下载并校验 minisign 签名；进度通过事件推送，包暂存在内存。测试渠道直接拒绝 | REQ-012 |
| downloaded_update_version（已实现） | 无 | 返回已下载待安装的版本号，供设置页重建状态 | REQ-012 |
| install_update（已实现） | 无，用户点击触发 | 安装已校验的更新包：macOS 替换 `.app` 后重启，Windows 启动 NSIS 安装器并退出；免安装 exe 与测试渠道直接拒绝 | REQ-012 |

授权输入通道必须按平台实际能力设计；不为方便而把 Keychain 内容或原始响应回传前端。若某平台需要手动输入秘密，应先设计合适的受控输入通道，而不是在普通前端状态或日志中保存。

### 10.2 状态与事件

- 两个界面订阅统一状态变更通知；建议事件带应用会话标识、递增修订号及受影响对象标识。
- 事件不是唯一数据来源。窗口首次打开、重连或发现版本缺口时读取完整脱敏状态，避免漏事件导致永久不同步。
- 同一会话内忽略过期修订，应用重启后按新会话重建状态，不比较不同会话的修订号。
- 不广播秘密、完整平台响应或账户私有路径。授权流程事件仅包含流程标识与安全的状态提示。
- 更新下载进度使用单独的 `update-download-progress` 事件，只包含已下载字节数与可选总大小；Rust 侧按 120ms 节流，收尾补发一次完整大小。
- 中转站条目使用 `relay-accounts-changed` 事件广播完整脱敏列表与递增修订号；`relay_list` 返回同样的结构，用于窗口重新显示时对齐。
- 接收 IPC 时由 Rust 校验产品类型、本地标识、设置范围与允许的操作；不信任前端传入的任意 URL、路径或 shell 片段。

### 10.3 平台适配器职责

建议围绕必要职责设计内部接口，不先建设可动态加载的插件框架：

1. 声明已验证的接入方式与数据能力，区分支持、未知和不支持。
2. 校验并关联账户身份，凭证通过后端安全存储访问。
3. 查询只读额度并转换为内部快照，保留真实单位、周期、时间与缺失字段。
4. 区分网络、限流、授权失效、无权限、不支持与数据格式变化；只返回脱敏错误及可靠的重试信息。
5. 在平台允许且验证安全时续期授权；不是所有适配器都必须具备自动续期。
6. 对主动导入明确来源、读取范围、续期所有权及与源工具共存条件。

Token Plan 个人版与 Coding Plan 中国站分别验证，不通过推理调用探测额度，不将团队席位 OpenAPI 直接当作个人版查询接口。

## 11. 测试与设计门禁

| 场景 | 预期结果 | 层次 |
| --- | --- | --- |
| 额度字段缺失、真实零额度、只有比例 | 各自表达未知、零或比例，不互相替代 | 适配映射与模型单元测试 |
| 已用比例来源与剩余比例展示 | 正确区分或转换，低额度判断基于剩余口径；只用合成测试值，不复制用户截图数值 | 适配映射、展示及提醒测试 |
| Credits、请求次数、未知单位并存 | 不错误相加或转换为 token | 模型及展示测试 |
| 个人订阅月与多个请求窗口 | 采用各自来源规则，不按固定自然月或固定 Codex 窗口推算 | 适配映射测试及真实来源核对 |
| 同平台两个账户、同账户多个套餐 | 凭证、缓存、错误、刷新及提醒隔离 | 服务集成与真实接入验证 |
| 双窗口同时刷新、连续点击 | 复用同一后端状态，同对象请求去重 | 服务及桌面测试 |
| 断网、限流、失效授权、解析失败 | 保留成功快照，分别反馈；网络故障不触发登录提醒 | 服务及故障注入测试 |
| 移除或重新授权时旧请求返回 | 不复活账户，不覆盖新授权数据 | 并发与状态测试 |
| 文件写入或 Keychain 操作失败 | 不报告假成功、不串号、可恢复 | 存储故障测试 |
| 重复刷新、重启、周期切换 | 按可靠周期去重，真实更新后才判断恢复 | 提醒及持久化测试 |
| 通知被拒、自启设置失败 | 状态与系统一致，额度查看仍可用 | 桌面权限测试 |
| 关闭管理窗口、休眠恢复、明确退出 | 常驻正确、恢复不补发大量任务、退出后不再查询 | 桌面运行测试 |
| 两架构从全新环境下载 DMG | 验证安装及业务，明确未公证限制，不依赖作者登录态 | 发布验收 |

测试可使用明确标记的合成样例，但测试通过不等于平台接入验证完成；生产界面不得以测试数据冒充真实额度。性能与最低系统版本的支持声明必须有实际验证依据。

## 12. 仍需验证后定案

- 三类套餐允许的独立查询授权与来源、实际响应、续期与导入共存条件。
- 字段级 Rust/TypeScript 类型、平台映射、权限与错误契约、JSON 版本及迁移策略。
- 刷新间隔选项、限流退避参数、缓存过期口径、提醒周期未知时的处理。
- macOS 最低版本与验证设备、Tauri 双架构打包与 ad-hoc 校验、实际发布渠道。

这些技术未决项通过能力验证与工程评审解决，不再作为追加产品功能的理由。业务实现和外部发布仍需后续明确指令。
