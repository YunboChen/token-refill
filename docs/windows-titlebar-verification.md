# Windows 自绘标题栏验证清单

标题栏按平台分治（见 `AGENTS.md` §4、`docs/requirements.md` DEC-029）：macOS 使用系统 Overlay 原生标题栏，Windows 关闭系统装饰、由前端 `TitleBar` 自绘。macOS 侧已在 2026-10-28 实机确认；Windows 侧只能在 Windows 实机上验证，请按本文逐项执行并填写记录。

## 1. 范围

- 主窗口 `main` 的自绘标题栏、拖拽、最小化 / 最大化 / 关闭与窗口常驻行为。
- Windows 10 / 11 x64，MSVC 目标。
- 不覆盖：tray 面板定位、应用内更新安装、NSIS 安装/卸载；这些见 [Windows 兼容设计](./windows-support.md) §9。

## 2. 前置条件

- Windows 10/11 x64，已安装 WebView2（Win10/11 通常预装）。
- Rust 使用 `stable-x86_64-pc-windows-msvc`；`tauri dev` 不读取 `RUSTUP_TOOLCHAIN`，必要时用 `rustup default` 或目录级 override。
- Node.js ≥ 22.12、pnpm 12。
- 命令：

```powershell
pnpm install --frozen-lockfile
pnpm build
pnpm tauri dev
```

如只需构建验证，可另跑：

```powershell
cargo fmt --manifest-path src-tauri/Cargo.toml --check
cargo clippy --manifest-path src-tauri/Cargo.toml --locked --all-targets -- -D warnings
pnpm test:rust
```

## 4. 已知限制（不记为缺陷）

- Windows 11 悬停最大化按钮不会弹出贴靠布局（snap layouts）：自绘标题栏没有 `HTMAXBUTTON` 命中测试。`Win+方向键` 贴靠仍可用。
- 没有系统边框后，`Alt+Space` 系统菜单不可用。
- 自绘标题栏的窗口阴影由 Tauri 默认处理，不做自定义。

## 5. 失败时的处理建议

- 第 1 项出现原生边框闪烁：把主窗口配置为 `visible: false`，在 `setup()` 中先 `set_decorations(false)` 再 `show()`；修改后必须重跑 §3.1。
- 拖拽或缩放失效：确认 `decorations` 只在 Windows 运行时关闭，未误改 macOS 分支；检查 `tauri.conf.json` 的 `resizable` 与 `minWidth` / `minHeight`。
- 按钮无响应：检查 `src-tauri/capabilities/default.json` 中的 `core:window:allow-*` 是否被削减，以及是否在控制台出现权限错误。
- 关闭后进程退出：检查 `src-tauri/src/tray.rs` 的 `CloseRequested` → `prevent_close` + `hide` 分支是否被改动。
